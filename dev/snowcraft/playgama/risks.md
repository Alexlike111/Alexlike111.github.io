# SNOWCRAFT · risks for the Playgama submission

Written 2026-11-10 from the repository as it stood then. Claims were checked with grep and by running the unit tests. Where a claim could not be checked, it is marked **verify**.

## Top five risks

1. **R1 · sound is generated in code (rule 3.3.2). BLOCKER.** Playgama does not accept sound synthesised in code. Every sound in the game is.
2. **R2 · save data uses IndexedDB and localStorage (rule 3.2.1). BLOCKER.** The world save is in IndexedDB, and the built HTML still contains `localStorage` references.
3. **R3 · the game takes its language from the browser (rule 3.4.2) and has no Bridge at all (rule 1.1.1, required steps). BLOCKER.** PG1 is on it.
4. **R4 · six strings have no translation in any language (rule 3.4.3). BLOCKER.** Players see Russian in every other language.
5. **R7 · generated visuals (rule 4.3.1). HIGH RISK.** The art is procedural code. Playgama rejects games built entirely from generative AI without human refinement.

## Detail

### R1 · sound (rule 3.3.2) · BLOCKER · owner: lead and owner

**Facts.** `src/engine/audio.ts` says in its first lines: "Every sound is synthesised at runtime with WebAudio (no files)." The `sfx` object plays 95 names, plus 10 internal ones (footsteps, drip, creak). The three gramophone records (`rec_1`, `rec_2`, `rec_3`) are also synthesised notes (DESIGN §15).

**Why it matters.** Rule 3.3.2 says the sound must be recorded or produced with audio tools and shipped as ogg or mp3. "Sound synthesized in code, such as procedural Web Audio tones generated by an AI coding agent, is not accepted." That is the exact case here.

**What is needed.** Real audio files. A sound designer or an audio tool must make every name in the list below. The procedural engine stays as a fallback only in the preview build.

**Proposed loading architecture.**
- Put each cue as an ogg (and an mp3 fallback) in the archive under `audio/`, with a small `audio/manifest.json` listing name, file, length and loop flag.
- Load them with `fetch` relative to `index.html` (the archive serves them from its own folder, no external calls).
- Decode with `AudioContext.decodeAudioData` after the first user gesture (the unlock already exists at `src/engine/audio.ts` around line 664, on `pointerdown`).
- Keep the procedural engine only in the preview build, behind a build flag, so it never ships in the Playgama archive.
- Do not bake the procedural sounds into files as a shortcut. Rule 3.3.2 still applies to output of code synthesis, even when it is written to a file. `renderOffline()` in `audio.ts` can render them, but that does not satisfy the rule.

### R2 · saves and storage (rule 3.2.1) · BLOCKER · owner: PG1

**Facts.**
- `src/game/save.ts` line 73: the world save uses `indexedDB.open` (one slot). Rule 3.2.1 forbids IndexedDB.
- `src/platform/store.ts` is the right seam: reads come from a cache, writes go to a backend. The backend in the preview build is `localStorage`. The Bridge backend is planned as `src/platform/bridge.ts`.
- `dist/index.html` (built 2026-11-10 09:48) contains 15 `localStorage` references and 1 `indexedDB` reference. Most come from `store.ts` (`localBackend`) and from the code that still calls `localStorage` directly.
- Settings already use the store. `src/engine/zoom.ts` and `src/game/seasons.ts` use it too (verify for every key).

**Why it matters.** Moderation reads the archive. A static reference to `localStorage` in the shipped bundle is a finding even if it never runs.

**What is needed.**
- PG1 moves the world save to the store (a single key with the serialized world, or chunked keys if the size is too big for one `set`; check the 3 MiB guidance in the saving guide before choosing).
- The Playgama build must not contain the `localBackend` code. Put the preview backend behind a build flag, and check the bundle with a grep for `localStorage`, `sessionStorage`, `indexedDB` and `document.cookie`.
- Batched writes: "write only on meaningful change, all keys in one call" (RS4). The current autosave every 30 s (`src/ui/title.ts`) must not add a write every frame.

### R3 · Bridge not integrated (rules 1.1.1, 1.1.2) · BLOCKER · owner: PG1

No Bridge code exists in `src`, and no `game_ready`, `showInterstitial`, `isAudioEnabled` or `platform.language` call exists. Required steps 1–8 are in `compliance-matrix.md` section A. The biggest change is the boot order: the SDK script goes first in `<head>` and boot waits for `initialize()`. Today `index.html` loads the game as a module at the end of `<body>`.

### R4 · six untranslated keys (rule 3.4.3) · BLOCKER · owner: lead

Keys missing from all nine packs (`src/content/lang/{ar,bn,en,es,fr,hi,id,pt,zh}.json`), present in `_source.json`:
- `drift.warn`
- `hunt.flockHint`
- `note.n14_x`
- `note.n2_x`
- `tools.digLooseFirst`
- `tools.shovelFull`

`tr(key, fallback)` in `src/content/i18n.ts` returns the Russian source when the pack has no key. So English players see Russian for these six strings. The fix is to translate them and to run `scripts/i18n-check.mjs`. After any change to a Russian source text, `scripts/i18n-invalidate.mjs <key>` must be run (AGENTS_W5 and playtest rules).

Related: rule 3.4.1 says English must be the fallback. The current fallback is the Russian source. The lead changes `tr()` so the fallback is `en`.

### R7 · generated visuals (rule 4.3.1) · HIGH RISK · owner: lead and owner

**Facts.** The code is AI-assisted (the project was built by AI agents). The art is procedural pixel art made in code (`src/art/*.ts`, `src/engine/tex.ts`, `src/engine/sprites.ts`). No human-drawn asset exists. The text is AI-written in ten languages.

**Rule.** Playgama accepts AI-assisted games, but "100% AI-generated games without substantial human refinement of the visuals" are rejected. Rule 4.3.1 also says games "shouldn't be built entirely" from generative AI.

**What human refinement would count.**
- A pixel artist redraws the title art, the cover, the icon, the player sprite and the igloo by hand, on top of the procedural base.
- A human designer chooses and places the content (locations, notes, animal behaviour) and writes the final copy. The copy must not be published without review.
- A human sound designer replaces the sound (R1), which also counts as refinement.
- The owner decides how much to invest (D7).

### R8 · violence and blood (rule 4.1.1; partner rules) · RISK · owner: lead

- Bear attacks; the bear is a death cause ("медведь").
- Harpoon hits on animals spawn blood particles (`src/game/tools.ts` line 644; `src/game/fauna.ts` line 293).
- Seal butchering and fish and bird catching.

Nothing graphic is intended. Blood particles are small, but the effect must be checked on the phone and in the screenshots. Game Distribution's rule (no explicit blood on screen) is stricter than Playgama's.

Action options: lower the blood effect for animals, make hits a snow-puff or a flash, keep the bear at a distance in the store images.

### R9 · browser and device coverage (rule 1.7.3) · RISK · owner: lead

Only headless Chromium was used in automation (`tests/e2e.mjs`, `tests/play/*.cjs`, `tests/ui-shots.mjs`). Safari, Firefox, Edge, Opera, iOS and Android are not tested. Touch is partly modelled in the tests (`page.touchscreen`), not proven on hardware.

### R10 · onboarding and fun (rule 3.1.3; quality) · RISK · owner: lead and owner

- Five persona playtests scored fun 4, 4, 4, 4, 6 out of 10 before the v13 fixes (`playtest/v13/FIXES.md`). Novice ratings were 3–6 (`playtest/v13/novice.md`).
- The owner's own verdict (playtest/PRIORITIES.md, 2026-11-07): "the game is good but not playable and not interesting". Top three pains: unclear goal, clumsy controls, nothing happens.
- X1 (goal line, coal placement, stove, cold guidance) and X3 (world content) are marked done in the git log (`52396c7`). X2 is marked merged. Each item was not re-verified here. No new playtest after the fixes exists (verify).
- Design §20 (from scratch, no start shelter, everything found and built) is a draft (`design/from-scratch.md`). The current code still has the station-centred start. Rule 3.1.3 expects a clear tutorial, and the from-scratch plan is the riskiest change to make before submission.

### R11 · balance (not a Playgama rule; affects retention and rule 3.1.2) · RISK · owner: owner

The balance bot (`tests/balance/report.md`, 2026-11-10) did not reach its targets:
- Мягкая: median 10.0 days (target over 30).
- Обычная: median 8.2 days (target 15–20).
- Суровая: median 13.1 days (target 8–12). Harder than Обычная is not the intended order.
- Cause, according to the report: fuel economy in the bot (driftwood and sealing), with the owner's target numbers unchanged. Raising the driftwood stock to 150 per ring moves Обычная to 19.1 days, in target.
- A closed stove damper in a locked house produces carbon monoxide (0.6 → 3.1 in 6 game minutes), which the bot found by accident.

### R12 · performance and memory (rules 1.3.3, 1.7; owner's phone test) · RISK · owner: owner

- FPS is not measured in cloud browsers and must be measured by the owner on a phone (SPEC §8, AGENTS_W5).
- The world is 2048×768 cells with several typed arrays, plus chunk sleep (`src/engine/grid.ts`). The memory figure "6 MB grids" in earlier notes is unverified.
- The build is a single 1.9 MB HTML file. The audio files will add to the archive.

### R13 · first-session length and clarity · RISK · owner: lead

The day clock was halved to about 20 real minutes per game day (`playtest/v13/FIXES.md` X3.1). The first night comes later than in v13 (verify). The first storm is in the first 20 minutes, which is a good hook, but the first hour is still unproven.

### R14 · originality (rule 4.2.2) · RISK-verify · owner: publishing chat

The game draws on sandbox survival and falling-sand ideas (DESIGN §20 names Noita as the physics reference). The controls follow a Terraria-style mapping, but no Terraria asset, name or text is used. The publishing chat should search the catalog before the first upload (`get_game_categories` lists examples per category).

### R15 · fonts and licences (rule 4.2.1) · verify · owner: lead

Pixelify Sans and Jura come from `@fontsource` (`package.json`). Both are under the SIL Open Font Licence. Check whether the archive must carry the licence text.

### R16 · player-visible self-test · low · owner: owner

The title screen shows a "Самотест" button, and the report text is Russian and developer-facing (SPEC §11). It runs no harm, but a store player may press it and see tests. Decide whether to hide it in the Playgama build (D18).

### R17 · translation quality · RISK · owner: lead

The nine packs were produced by translator agents from the Russian source. Native review has not been done. The store texts in `store-listing.md` need native review too, especially Arabic (RTL layout check) and Bengali.

### R18 · leftover methane code (DESIGN §16) · low · owner: lead

DESIGN §16 removes methane. The code still has a `methane` site (`src/game/locations.ts` lines 24, 81, 98), a sealed "methane pocket" in the mine, and `purgeMethane()` (`main.ts`). `tests/mine.test.ts` checks the sealed pocket. None of this is visible to a player as methane, but it is dead design and should be removed or renamed before submission.

### R19 · lore and names · low · owner: none

The 1890s expedition, the ship «Заря», the station «Мыс Безмолвия» and the mine «Шахта №3» are fictional. Verify no real person or real expedition is named in the notes (`src/game/lore.ts`, 26 notes).

### R20 · partner platforms · owner decides · see compliance-matrix section F

Choosing a partner changes the rules. Some ban outgoing links or blood on screen. Some need portrait, which the game does not support. Some need Russian as the default.
